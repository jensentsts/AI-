/init 项目主要采用 【】 实现，进行一个 【】 。项目可能分为多个子项目，使用驼峰命名。

以python语言为例，给出的规范如下：

1. 交互与依赖
   - 使用 Ask 面板逐步询问决策，提出多个方案时调用面板让我选择。
   - 优先采用开源库，用 pyproject.toml + 依赖锁定管理依赖，避免造轮子。

2. Git 管理
   - 项目伊始，初始化 git ，此后所有写操作必须经我明确指示；可自主更新 .gitignore。
   - 绝不提交 API Key、数据资源等。
   - 不得擅自切换分支；执行 Git 写操作前检查当前分支是否符合当前任务要求，不符合时使用 Ask 面板询问。

3. 代码架构与质量
   - 追求算法效率，善用现代语言高级特性与语法糖。
   - 优先采用策略、工厂、管道等适合问题结构的设计模式。避免为了形式上的设计模式而增加不必要的抽象。避免大量条件分支和纯过程式代码；对于自然存在的分派关系，优先使用多态、策略或注册机制。
   - 以下扩展点必须定义统一抽象接口（优先使用 ABC 或 Protocol）：模型加载、数据预处理、评估指标、输出格式等。
   - 大对象惰性加载。
   - 长时间任务必须封装为可序列化的任务对象，保存足以恢复执行的状态，包括随机数状态、当前进度、配置、模型状态、优化器状态及必要的中间结果等。支持正常暂停、用户主动中断以及异常退出后的恢复。
   - 单文件不超过 1k 行，分离配置、数值与算法，底层、核心、调用分层。

4. 输出与测试
   - 图片输出同步保存 SVG 副本。作图源数据和图以相同名称（仅后缀差异）进行再保存。
   - 核心算法和数据处理编写关键测试，后续随功能增量添加。

5. 文档
   - 必须提供 README.md（简介、安装、运行、测试、目录结构）。
   - 所有公开接口使用 Google/NumPy 风格 docstring，复杂逻辑加模块级注释。
   - 算法和模型的部分给出关键参考文献链接，说明实现与公式的对应关系。
   - 在每次 git 写操作之前请主动更新文档。

6. 目录与配置
   - 生成内容放 dist/
   - 工具模块放 utils/
   - 神经网络模型放 model/（权重带时间戳，中断时保存；大数据、训练数据、权重不提交 Git；存权重的同时存架构，架构和权重保持同名存在同一目录）。
   - 全部文件路径集中在 path_config.py，使用 pathlib.Path，以类组织，并为各路径提供用途说明；禁止在业务代码中散落硬编码路径。
   - 项目配置/常量集中在 config.py，以类变量管理。
   - 日志使用 logging.basicConfig 集中配置；
   - 控制台上如果要有进度条，使用美观的现代库（不用 tqdm）。

7. AI agents 要求
   - 不得读取、创建、修改、删除 data/* 中的任何内容。
   - 破坏性变更前，首先备份好项目，特别是关键数据和信息。
