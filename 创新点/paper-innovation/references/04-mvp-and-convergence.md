# 阶段 4–5：前瞻验证、作者决策与论文交接

这份细则处理的是研究主张是否得到支持，不要求所有项目都跑仿真。测试方法、理论或现象时，应采用能区分主张与最近替代解释的最低成本证据。

## 1. 先锁定规则，再观察结果

在第一项测量、运行、结果解读或针对数据的探索发生前，填写 `04_mvp_verification.md` 中的主张、适用条件、可观测结果、证据来源、`ADVANCE / REVISE / STOP` 规则和 `PENDING`（无法判定）情形。阈值要来自设备/运营约束、目标理论精度、已知测量波动或作者确认的科学目标，并说明为什么有意义；同时写清统计/测量不确定性及基线自身的合理性检查。不要用固定百分比或测完后更换主指标。

测量前锁定当前提案的预注册。示例命令如下：

```powershell
$ctl = (Resolve-Path 'E:\__ai__\焚诀\创新点\paper-innovation\scripts\ideation_ctl.py').Path
python "$ctl" lock-prereg --dir 'E:\workspace\project-a\ideation' --proposal P2
python "$ctl" check --dir 'E:\workspace\project-a\ideation' --proposal P2 --gate 3
```

锁定材料应绑定到稳定版本。若后来确需更改判定规则、主指标或范围，建立新版本（例如 `P1-v2`），保存旧版及结果为探索性记录，另做独立红队审查，取得作者对新版本的决策点 1 选择，并重新锁定后再测新版本。没有锁定记录的既有测量只能标为探索性证据，不能伪装为前瞻验证。

并行提案和返修版须显式带 `--proposal`，使提案专属的 `04–06` 写到 `runs/<提案编号>/`，共享的 `01–03` 留在根目录。对这类提案运行 `lock-prereg` 与 `check` 时始终传相同编号；不传编号会走兼容旧工作区的根目录文件。

## 2. 根据主张做检验

### 方法主张

对照 `M0`（经典方法）、`M1`（有依据的近期对手）、红队定义的强朴素基线 `M2`、完整方法 `M3`，并至少有一个与主机制对应的命名消融。保证数据、信息集、硬约束、硬件、求解容差、调参和计算预算可比。`primary_metric` 要对应带单位的精确表头，`metric_direction` 写 `min` 或 `max`，`min_difference` 填一个正数，表示 `M3` 相对 `M2` 达到的绝对差值，并按该表头单位计；例如百分比指标用百分点表示，字段中不重复写单位。阈值来源须说明。`uncertainty` 记录随机种子数、区间或测量误差及其限制。报告消融和预先列出的伪胜出核验。标明数据来源与 `M1` 复现保真度；使用现场/运营观测数据时标明 `observational-data`。`M2` 不可设置成稻草人。

小基准要保留造成原问题的关键约束或失效机制。仅当论文主张可扩展时才加至少两个规模点，记录规模、时间、内存、硬件与误差/可行性；一次小规模胜出不能支撑大规模结论。测试范围和资源不足时缩小主张，不能把模拟代理说成真实系统验证。

### 理论主张

与最近命题并列假设、结论及适用参数域，检查可推出方向。若主张新结果更强，尝试构造满足旧命题前提但使新结论不成立的参数/状态见证；若主张改进算法，核对证明前提、复杂度或收敛条件并给出可复核的完整推导/比较材料。结果应绑定到实际证明文件、公式或反例，不以数值性能替代理论差异。

### 现象主张

至少给两种竞争机制，并为每种事先写出在何种条件下会观察到什么、什么结果会削弱该解释。核对每个预测所需的原始数据、时间戳、空间/主体粒度、缺失字段和替代因素；有些数据取不到时，设计可用观测范围内的判别并保留其余机制为待检验。相关变化本身不证明因果机制。

### 匿名示例（仅说明工作流，不是事实或证据）

假设研究者提出：“一个匿名地区的部分场站在负电价时段降低出力。”先把主张标为 `phenomenon`，不从这句话推断真实机制。候选解释 A 是调度限发；候选解释 B 是合同/结算激励下的主动减发。A 预测出力下降与调度限发记录、可发功率约束同步；B 预测结算规则与时段价格可解释差异，即使没有相应限发指令。先问能否按时间对齐取得结算条款、可发功率、限发指令和实际出力，并登记数据来源。关键记录无法取得时，标记 `PENDING` 并将主张收窄到现有观测支持的范围。这个例子没有报告任何真实场站结果。

## 3. 结果、风险备忘录与 Gate 3

每个结果记录判定、实际观测、来源/原始文件、是否达到预设门槛、不确定性、反例和与预注册的偏离。偏离必须说明发生时间、原因及其属于探索性修正还是新提案；对基线失败先排除实现错误、输入不对称和不合理配置。结果用 `ADVANCE / REVISE / STOP / PENDING` 表述，不能只写“效果好”。

在 `05_internal_flaw_memo.md` 记录当前证据的限制、敏感范围、风险和可选处置，供作者决策；不要把它交给论文写作上下文。Gate 3 只检查这份材料的前两节和隔离标记，不要求作者决定点 2 的回应已完成；作者批复部分留到 Gate 4。只有作者实际在决策点 1 选择 `PASS` 路线后才能进入 Gate 3：

```powershell
$ctl = (Resolve-Path 'E:\__ai__\焚诀\创新点\paper-innovation\scripts\ideation_ctl.py').Path
python "$ctl" check --dir 'E:\workspace\project-a\ideation' --proposal P2 --gate 3
```

Gate 3 可以准备完整的 `REVISE` 或 `STOP` 结论供作者决策；这两种结果不会交接到论文撰写。随后提交**决策点 2**：呈交真实测量/证明/观测材料、证据状态、预注册对照、风险与下一步选项，由作者选择锁定、返修或终止。不得自动进入 Gate 4。

## 4. Gate 4：作者批准后收敛贡献

仅在作者于决策点 2 明确批准 `ADVANCE` 后整理最终交付。填写 `05` 的作者回应部分：作者、日期、每项风险的处置及确认的适用边界；不得提前替作者填写。完成 `06_final_contributions.md` 的贡献、章节、公式/图表、实验和实际证据对应关系；用稳定引用（如 `04#evidence:M2`、`04#evidence:witness`、`04#evidence:A`、`04#result:boundary`）绑定到真实填写的证据行或结果字段，核查引用与证据路径可访问、贡献表述不超出证据。再运行：

```powershell
$ctl = (Resolve-Path 'E:\__ai__\焚诀\创新点\paper-innovation\scripts\ideation_ctl.py').Path
python "$ctl" check --dir 'E:\workspace\project-a\ideation' --proposal P2 --gate 4
```

稿件只接收经作者确认的适用范围，并将其写成研究问题的条件或对象设定。未确认的局限仍留在内部备忘录；不要让内部风险清单进入稿件上下文或将尚未确认的边界写成事实。
