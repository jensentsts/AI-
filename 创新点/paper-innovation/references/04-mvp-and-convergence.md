# Phase 4 & 5 Reference: Pre-Registered MVP Verification & Contribution Convergence

本细则用于阶段 4（最小原型仿真验证与残差迭代）与阶段 5（三层贡献收敛与写作移交）。

---

## 阶段 4：预注册最小原型仿真（MVP）协议

### 4.1 跑代码之前：锁定预注册判定规则与不可判定检查（防事后画靶）
在运行第一行 MVP 对比实验**之前**，必须在 `ideation/04_mvp_verification.md` 中先行写死：
1. **预注册 Advance / Revise / Stop 阈值规则**：
   - **Advance（锁定晋级）**：在核心指标 1/2 上相对 `M2` 与 `M1` 达到明确且具备工程意义的领先幅度（同时硬约束越限率不劣于基线，且每个消融变体均出现预期退化）；
   - **Revise（残差修正）**：出现清晰、有结构的局部失利或异常残差，值得投入最多 2 轮机理修补；
   - **Stop（止损弃题）**：2 轮内仍无法在公平条件下稳定胜过 `M2`，或领先幅度小于噪声/随机波动区间。
   - **纪律**：实验跑完后严禁悄悄篡改上述门槛或把原本主打的指标偷偷换成无关的次要指标；若根据残差调整了目标设定，必须在迭代日志中显式标注为「探索性修正」。
2. **不可判定工况 / 基线合理性核验（Indeterminate Outcome Check）**：
   - 在解读胜负前，先确认是否存在“结果不可判定”的工程错误：例如 `M1`/`M2` 是否因为代码 Bug、初始化不当或求解器错误配置而异常崩盘？对照基线自身的数值量级是否与原文献报道一致？只有通过合理性核验的对比数据才允许进入分流裁决。

---

### 4.2 算例设定与四组强制公平对照
1. **最小但保留真病灶**：
   - 选用目标领域公认的小规模标准算例或精简公开数据集（如 IEEE 14/33/39 节点系统、公开风光/负荷切片等），单轮运行控制在秒级～分钟级；
   - **底线**：缩小算例绝不能把核心难点退化掉（必须保留紧约束、强非凸、大扰动或极端分布工况）。
2. **强制四组公平对照（同一数据、同一硬件、同一容差与物理校验口径）**：
   - `M0`（经典/传统基线）：领域广泛使用的标准方法；
   - `M1`（近期 SOTA）：阶段 1 `full-text` 矩阵中的代表性近 5 年顶刊方法；
   - `M2`（强朴素适配版）：阶段 3 红队亲手定义并登记的最强简化对手；
   - `M3`（本文完整方案）+ 逐模块消融变体（`M3 w/o Module A`, `M3 w/o Module B`, …）。
3. **逐项完成「虚假胜出排查（Apparent-Win Artifact Audit）」**：
   - 针对阶段 3 红队登记的伪原因，逐条核验并写明证据：（a）基线与本文方法的调参预算是否对等；（b）是否存在数据/未来信息泄露；（c）求解器容差与硬约束越限判据是否完全一致；（d）跨多组随机种子或扰动工况是否保持稳定胜出。

### 4.3 实测结果三分流与「残差驱动二次修正」

| 实测情形 | 判定 | 执行动作 |
| :--- | :--- | :--- |
| **情况 A：稳定且显著胜出**（满足预注册 Advance 规则，通过虚假胜出排查，各消融变体呈现预期退化） | 创新机制获实证闭环 | 倒推有效机理，提炼可写入正文的数学性质（Proposition / Remark）或清晰物理解释；补齐 `05_internal_flaw_memo.md` 后触发**决策点 2**。 |
| **情况 B：局部失利或反直觉残差**（整体或部分工况未拉开与 `M2` 差距，但误差分布、迭代曲线或越限节点呈现清晰规律） | **高价值创新信号** | 启动 **残差驱动二次修正（最多 2 轮）**：<br>1. 专门定位失败工况的残差/越限/不收敛根因；<br>2. 针对根因修补模型或算法结构（而非盲调超参）；<br>3. 重跑完整四组对照并如实记录修正前后变化（标注为探索性修正，必要时换新测试切片复核）。 |
| **情况 C：天花板锁死或仅靠玄学调参险胜**（2 轮内仍无法稳定击败 `M2`，或收益在随机波动误差内） | 路线证伪 | 停止继续堆砌，如实记录失败复盘与耗费成本，在**决策点 2** 明确建议人类**果断弃题**并切换备选路线或重开阶段 1。 |

### 4.4 双轨缺陷纪律（强制文件隔离）

将 MVP 中暴露出的**全部**边界条件、计算短板、理论近似前提、超参数敏感区间与大算例扩展隐患，**如实写入 `ideation/05_internal_flaw_memo.md`**，并为每条风险提供 2～3 个可执行的工程处置选项供人类在决策点 2 拍板。

> **严禁越界规则**：
> - `05_internal_flaw_memo.md` **仅供人类作者与内部评审阅读**，严禁传入后续论文写作上下文；
> - 经人类拍板确定的适用边界，在正文中自然作为“研究问题设定/工况范围”呈现，绝不出现“本文方法这里做不了、哪里不代表”等自我拆台或过度防御句式。

完成 `04_mvp_verification.md` 与 `05_internal_flaw_memo.md` 后执行门控校验：
```bash
python scripts/ideation_ctl.py check --dir ideation --gate 3
```
随后暂停，向人类提交 **决策点 2 简报**（真实数值表 + 虚假胜出核验 + 内部缺陷备忘录 + 锁定/修正/弃题选项）。

## 阶段 5：三层贡献收敛与写作移交

经人类在决策点 2 批准锁定后，生成最终交付物 `ideation/06_final_contributions.md`：

### 5.1 「1 主线 + 2～3 条递进贡献」封装标准
- 严格收敛为 **2～3 条**，彼此构成**因果递进链**（不并列凑数）：
  1. **贡献 1（问题 / 建模层）**：针对某具体场景痛点，揭示并形式化刻画既有研究忽略的关键机理/耦合/约束；
  2. **贡献 2（方法 / 算法层）**：针对该模型带来的求解/泛化/安全瓶颈，提出定向数学重构或算法机制，打破原有核心权衡；
  3. **贡献 3（理论性质 / 工程验证层）**：在收敛性、可行性保证、复杂度或大规模/极端工况鲁棒性上给出明确理论剖析与充分实证。

### 5.2 题目具象化与术语克制最终核验
1. **题目核验**：避免空泛大标题，明确体现“**以具吸引力的具体方法/机制，解决了某具体场景下大家关注的核心难题**”。
2. **术语克制核验**：逐词审查贡献与框架命名——行业已有确定化常态表述的一律复用，全篇原创命名不超过 1～2 个，且仅用于指代真正的新结构。

### 5.3 全篇总控映射与最终校验
在 `ideation/06_final_contributions.md` 中完整建立 **「创新点 → Introduction 铺垫 → 章节公式 → 示意图/对比图 → 大/小实验与消融 → MVP 锚定的量化优势」** 的一对一映射，确保后续正文写作前有铺垫、后有呼应、图文分工清晰。

执行最终门控校验：
```bash
python scripts/ideation_ctl.py check --dir ideation --gate 4
```
通过后，仅将 `04_mvp_verification.md` 与 `06_final_contributions.md`（**严禁包含 `05_internal_flaw_memo.md`**）移交至下游大算例扩展与论文撰写阶段。
