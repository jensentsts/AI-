# 构思上下文隔离与证据调用协议

目的：新候选只能从作者的问题、独立观察/约束/推导与经筛选的来源接口构造。生成器不得看到论文内容、标题或摘要，也不得借用作者 Future Work 预先提示候选路线。隔离生成不等于新颖性成立；须由红队独立核验。

## 1. 划清问题与来源对象

- **`Q#` 问题来源**：用户给出的研究问题/种子、独立观察、真实约束或独立推导。它们提出要解释或解决的问题，不包含从论文中照搬的“下一步方案”。来源类型和简短出处可核验。
- **`L#` 可调用来源对象**：论文或数据资源中的方法、定理、数据集、约束、基线或事实。用于构思的论文型 `L#` 必须在 `01` 来源登记（批量初筛时可用 `00` 的小型登记）中有稳定 ID/本地文件定位、全文已读标记及具体页码/公式/图表定位。生成简报只给接口：输入、前提、已知操作/结论、输出和适用边界，不给题名或原文。调用 `L#` 本身不是创新。
- **允许不调用文献**：只要存在独立 `Q#`，就可不带 `L#` 生成候选，并将调用标记为 `NONE`；不必为了填表或显得新颖而硬凑文献。
- **原文审查登记**：论文题名、摘要、原文、检索响应和作者 Future Work 放在独立的证据/审查登记区，绝不导出到构思简报。审查者可为核验先例独立查看原文。

## 2. 生成与交接

将经核验的 `Q#` 和合格 `L#` 登记在 `01`；batch 模式下可登记在 `00`。论文型 `L#` 若只有摘要、缺稳定来源标识或没有精确定位，不能成为简报中的调用对象，但仍可留在文献/红队登记中。审核允许字段后运行：

```powershell
$ctl = (Resolve-Path 'E:\__ai__\焚诀\创新点\paper-innovation\scripts\ideation_ctl.py').Path
python "$ctl" prepare-ideas --dir 'E:\workspace\project-a\ideation'
```

CLI 将已审核字段写入 `idea_context.md`，并报告该内容寻址的不可变快照及空白模板 `templates/idea_draft.md`。生成器只能看到**该快照文件和空白 `idea_draft.md`**；不得给它工作中的 `01`、`00` 或 `02`，候选历史、C 编号、真实 M1 论文/DOI、原始论文/PDF、摘要、Future Work、旧红队意见、项目历史或主会话对话。如此生成器不需要看到 C、M1 或论文原文；协调者在生成完成后再做来源匹配。

新上下文中由生成器填草稿：选择 `Q#`，必要时调用 `L#` 并在调用明细中写出**本题输入 → 来源输出 → 输出在候选主张中的作用**；再写作者增量、区分性预测及证伪条件。若已有来源对象已给出全部结论，应明确返回“无新增主张”，不要改写其结论冒充新提案。

收到完整草稿后，由协调者将它转录到工作中的 `02_candidate_proposals.md`，或 batch 的 `00_screening.md` 与候选来源/增量栏。**转录之后**才把它与最接近论文、C 编号、M1、DOI/页码证据配对；保留草稿里的原始 `Q#`、调用方式、`novel_delta`、预测与证伪条件，不用文献内容替换作者的问题或增量。不要把含有既有候选、C/M1 映射或红队笔记的工作文件回传给生成器。

P 记录 `origin_ids`（`Q#`）、`calls`（`L#` 或 `NONE`，及各调用的输入/输出用途）、`novel_delta`、`generation`（`fresh` 或 `author-supplied`）；fresh 草稿另附 `brief_sha256`，取自实际快照文件名。若不能建立不继承历史的生成上下文，交付审核后的简报并继续核验用户已给出的想法；如仍在同一上下文生成，明确标记 `unisolated-fallback`，不得称为干净隔离生成。

## 3. 独立红队判断来源关系

红队审查者独立打开最接近论文全文，核对 Related Work、方法/定理内容及 Future Work，并对候选与先例的关系标为下列之一：

| 标签 | 含义 |
| --- | --- |
| `INDEPENDENT` | 文献未提出该路线；当前候选由独立问题和作者增量形成 |
| `KNOWN` | 文献已经报告相同或实质相同的主张/机制 |
| `PRIOR-SUGGESTED` | 原文作者已明确提出相同路线或关键增量作为未来工作 |
| `UNCLEAR` | 现有证据不能判断是否相同，需要补查或收窄 |

每个判断附来源定位和对应的 `novel_delta`。`L#` 被调用本身、把来源对象改名、或将原论文 Future Work 改写一遍，都不能证明新颖；`KNOWN` 或 `PRIOR-SUGGESTED` 不能给 `PASS`，`UNCLEAR` 须补证后再判。只有独立查重、研究意义、备选解释、假设/物理边界与可证伪检验均通过后，才可认为候选有资格进入人类决策。

## 4. 怎样判断调用后还剩下什么

假设一篇来源给出了在非负输入上成立的误差上界。把它登记为定理对象。调用时写明本题哪组量满足非负条件、代入什么量，以及返回的上界用在哪一步。若候选的全部结论就是代入后得到这个上界，记录“复用已有定理，无新增主张”，即可结束。

审查真正的候选时，将用过的对象及其已知输出逐一扣除。对仍然成立的作者主张，写清需要自行证明、复现或观测的那一步。若原作者已把这一步列入展望，同样登记为先例。即使跨课题、改写措辞或换了应用场景，也要保留这项归属。语义上的重合须回原文判断。
