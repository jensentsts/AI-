# 阶段 2：从证据构造可检验路线

本阶段先确认主张类型和工作条件，再决定需不需要构造算法。不要为了填满模板或达到候选数而制造方案。

## 1. 先定主张与最低成本检验

| 主张 | 要回答的问题 | 首个有区分力的检验 |
| --- | --- | --- |
| `method` 方法 | 新机制相对最强朴素改法，在哪个条件下改善哪个可观测结果？ | 同信息、约束、预算下比较强朴素基线与候选；预写主指标、方向、实际有意义的门槛及测量不确定性 |
| `theory` 理论 | 新结论与最近命题的假设、蕴含和适用参数域有何实质差异？ | 并列假设与结论，尝试双向推导；若声称严格更强，寻找满足旧条件但违反新结论的见证，或证明该见证不可能 |
| `phenomenon` 现象 | 哪些不同机制能解释观察，每种机制给出什么可区分预测？ | 先核对所需变量、时间戳和采样粒度能否取得，再比较竞争预测并设计替代解释检查 |

按贡献内容选择，而不是按工程学科或代码形式选择：若结论主张集合包含关系、严格更强的不等式、等价关系或定理，选 `theory`，即使定理服务于某个工程算法；若主张新方法改善实际决策/观测结果、约束可行性或求解器性能，选 `method`。对多题初筛，`init --claim` 仅提供默认类型，`00_screening.md` 中每行都要单独判断，并在后续单题 `init` 中传入该题的类型。

任何类型都先摸清资源与边界：可用数据/基准、数据许可、已有代码、硬件、求解器、时间预算和用户授权。若最关键数据拿不到或预算不足以区别主张，应把缺口写明并缩小范围；不要先承诺难以完成的方案。

生成新候选前先运行 `prepare-ideas --dir <课题目录>`，确认 `idea_context.md` 只含审核过的 `Q#` 问题来源和合格 `L#` 接口。用于构思的论文 `L#` 必须来自台账中全文已读、有稳定 ID 和具体页码/公式/图表定位的工作；abstract-only 条目、原始标题、论文原文和作者 Future Work 留在证据/审查区。没有合格 `L#` 时可仅用独立 `Q#` 并把 `calls` 标为 `NONE`。新上下文只能拿 CLI 报告的不可变快照和空白 `idea_draft.md`，不得见到工作中的 `01`、`02` 或 batch `00`。草稿返回后，由协调者把内容转录进 `02`/`00`，再链接 C、M1 与 DOI/页码，保留作者的原始问题和增量。每个 `P` 标出 `origin_ids=Q#`、`calls=L#` 或 `NONE`（附具体输入→输出用途）、`novel_delta`、`generation=fresh|author-supplied`；fresh 结果附实际 `brief_sha256`。详细输入/输出见[上下文隔离协议](05-context-isolation.md)。

`single` 可以只有一个候选，也可以先对一个明确想法做廉价否证。`batch` 先在 `00_screening.md` 比较候选和最低成本检验，不为每条题目做完整综述；每行给出 `KEEP / DROP / DEFER` 与依据。零条 `KEEP` 且至少记录一项实际决定是有效初筛。只有 `KEEP` 的候选才进入正式工作区。

## 2. 六个方法构造算子（仅适用于 `method`）

六个算子是寻找**方法机制**的工具，不是理论证明或现象研究的清单。每个候选须连到阶段 1 的具体证据与失效边界，再说明为何改动会改变可测结果。

| 算子 | 构造动作 | 需核验的因果链 |
| --- | --- | --- |
| `O1` 打破过时假设 | 把关键但被固定或忽略的机理纳入模型 | 旧假设在目标场景造成可复现损失；新增机制能解释并修复损失 |
| `O2` 破除结构性权衡 | 利用问题的代数、物理或稀疏结构改造建模/求解 | 解释为何指标前沿改变，不能只是调权重换取另一指标 |
| `O3` 去障碍同构迁移 | 借用相邻领域的成熟数学结构并处理迁移障碍 | 对照量纲/守恒、时间尺度、信息结构、变量与硬边界、规模增长律；指出不改造会在哪个假设或步骤失效 |
| `O4` 跨层闭环耦合 | 把原先割裂、相互影响的阶段联合反馈 | 量化割裂造成的目标失配或风险，并说明闭环成本可控 |
| `O5` 机理—数据硬边界融合 | 机理负责硬约束/主骨架，数据模块负责未知部分 | 说明模块各自不可替代，并设计能区分作用的消融/安全检查 |
| `O6` 定点重构已知失效 | 针对真实、重要且可复核的边界失效修复特定环节 | 失效不依赖人为刁钻设定；常规与边界工况都可检查 |

可用“约束阶梯”拓展方法路线：保留现实约束，识别一个惯性假设，再加入一个现实可解释的严格运行边界。这个动作只用于扩展候选，不足以证明创新。

## 3. 候选描述必须可反驳

每个候选至少记录：编号、`claim`、针对的文献判断、与最近工作的重叠及差异、核心假设、变量/机理或定理轮廓、最强替代解释、可区分预测、失败条件、所需数据/资源和最便宜的下一步。理论路线列出假设与参数域；现象路线对每个竞争机制写出不同预测及相应观测量；方法路线至少说明强朴素基线如何实现。

方法候选的预测必须落到主指标和实际问题：提前指定指标方向、工程/科学上有意义的差值门槛、误差或不确定性估计，以及会导致 `REVISE` 或 `STOP` 的结果。阈值从设备限制、运营需要、既有测量波动或作者确认的目标推导；不使用固定百分比，也不把“赢了某个比例”当作新颖性证据。

## 4. 反同质化与早停

有多条候选时，说明其机制为何不同，至少设置一条真正不同的替代路线；没有可靠的第二条时，保留一个强候选即可。剔除仅换网络/优化器名称、无耦合拼接模块、靠新术语包装常规调参、无法做消融或不能提出反例的路线。记录被淘汰项和理由，避免在后续会话中重新包装同一死路。
